# code-to-docs-update 使用指南

## 功能

**增量更新**已有文档。Git 提交后只重新分析变更的模块，合并结果而不重头生成。

## 使用方式

```
"更新文档"
"同步文档到最新提交"
```

## 使用示例

### 示例 1：修改代码后同步文档

> **你**: "我刚改了 NetworkModule 的重连逻辑，更新一下文档"

> **AI**: `git diff` 对比上次文档记录 → 仅重新分析 NetworkModule → 合并现有文档。

### 示例 2：多次提交后批量更新

> **你**: "从上次生成文档后我改了很多，更新一下"

> **AI**: 对比差异，识别所有变更模块，重新分析受影响部分，其余不变。

## 工作流程

```
1. 校验现有文档库
2. git diff 找到变更文件
3. 映射变更文件到模块
4. 自动选择 quick/full 模式
5. 仅重新分析受影响模块
6. 合并 issue 追踪（已修复/仍存在/新增）
7. 选择性重新生成受影响文档
8. 更新状态文件
```

## Issue 追踪规则

- **自动关闭**: diff 显示该 issue 指向的代码确实被修改过
- **保持 open**: 非确定性重分析没提到，但代码没变 → 不关闭
- **新增**: 新分析发现的问题

## 前提条件

- 已存在 `docs-vault/_state/analysis.json`
- 代码库是 Git 仓库
- 上次记录 commit 在当前仓库中可达

## 适用场景

- 日常开发中保持文档更新
- Code review 后同步文档变更
- 重构后的文档刷新

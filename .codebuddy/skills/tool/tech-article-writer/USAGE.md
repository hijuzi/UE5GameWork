# 使用说明

## 如何触发

在对话中提及以下关键词或场景时，会自动加载此技能：

### 直接触发
- "帮我写一篇关于 XXX 的技术文章"
- "分析这段源码并写文章"
- "写技术文章"
- "tech article" / "technical writing"
- "审查这篇文章" / "review this article"
- "优化这篇文章" / "改进写作"

### 间接触发
- 准备系列化技术内容
- 优化现有文章的结构
- 设计文章大纲
- 对已完成的文章做 AI 自审查

## 核心流程

```
需求确认 → 大纲设计 → 技法匹配 → 概念提取 → 设计思考挖掘
    → 源码定位 → _source-location.md 记录 → 图表规划
    → 逐段撰写（每引用新文件实时追加到 _source-location.md）
    → draw.io 配图 → AI 自审查（≥42分，含源码纠正 + 画图纠正）
    → 质量检查 → Humanizer 润色 → 交付
```

## 使用场景示例

### 场景一：从零起草一篇技术文章
```
用户：帮我写一篇关于 UE5 Enhanced Input 系统的技术文章
AI：加载技能 → 判断读者跨度（自动决定用标准五段式还是分层递进变体）
→ 按选定结构设计大纲 → 内部技法匹配
→ 逐段撰写 → AI 自审查 → Humanizer 润色 → 交付
```

### 场景二：分析源码后写成文章
```
用户：分析 UGameplayAbility::ActivateAbility 的实现，给我写一篇文章
AI：分析源码 → 提取核心概念 → 设计思考点 → 洋葱式逐层拆解（Jerish式）
→ 撰写文章 → AI 自审查 → 交付
```

### 场景三：规划文章系列
```
用户：我想写一个 UE5 GAS 系列文章，帮我规划
AI：设计系列目录 → 统一标题格式 → 规划每篇焦点（分层递进）
→ 预计篇数 → 学习路径图（Milo Yip式）→ 篇末预告
```

### 场景四：优化已有文章
```
用户：帮我看看这篇技术文章有什么可以改进的
AI：对照质量检查清单 → 执行 AI 自审查（五维度打分）
→ 利用 _source-location.md 定位源码，逐一比对文章中的代码引用
→ 校验所有 diagram 图与源码的一致性
→ 指出结构/深度/可读性/AI痕迹/准确性问题 → 给出具体到段落的修改建议
```

### 场景五：根据反馈迭代修改
```
用户：引言部分太啰嗦了，精简一下
AI：理解意图（精简）→ 定位引言段落 → 局部修改 → 上下文检查
→ 重新自审查（含源码纠正 + 画图纠正）→ 报告改动和分数变化（修改前 XX/50 → 修改后 XX/50）
→ 如有涉及代码或图表的新增内容，同步更新 _source-location.md
```

## 输出内容

每次输出包含四个部分：
1. **文章大纲**：确认方向和结构
2. **正文**：按五段式（或分层递进变体）展开
3. **`_source-location.md`**：记录引擎版本、涉及模块、以及文章引用的每个具体源码文件的引擎相对路径（写文章过程中实时追加）
4. **AI 自审查报告**：五维度打分 + 具体问题与修改建议，以及源码验证和画图验证专项结果（必须附带）

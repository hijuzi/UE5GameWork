>
> - **项目源码**：`GameWork/Plugins/GameplayAbilities/Source/GameplayAbilities/`（Public + Private）
> - **引擎基线**：`E:\EpicGames\UE_5.8\Engine\Plugins\Runtime\GameplayAbilities\Source\GameplayAbilities\`（同名文件）
> - 每一处修改都在代码中以装饰线 + **`GAS_MOD_xx START` / `GAS_MOD_xx END`** 成对包裹，包裹内按"修改前(引擎原版) / 修改后(本项目)"对照展示，便于直接检索 `GAS_MOD_` 定位所有改动。

## GAS_MOD 标记规范（固定格式，后续所有改动必须遵循）

每处相对引擎的源码修改，必须按以下模板包裹，其中"修改前"用 `/* */` 块注释**逐字**保留引擎原版代码（含原始缩进、注释与完整逻辑）：

```cpp
//=====================================================================
// ===== [GAS_MOD_xx] START=====
// 修改前(引擎原版):
/*
<引擎原版代码，逐字一致，含原始缩进、注释和完整逻辑>
*/
// 修改后(本项目, 新建): <改动说明，可多行>
//=====================================================================
<修改后的实际生效代码>
// ===== [GAS_MOD_xx] END =====
//=====================================================================
```

**规范要点：**

1. **装饰线**：`//=====================================================================`（无空格，紧贴 `//`）。
2. **START/END 标记**：`// ===== [GAS_MOD_xx] START=====` 与 `// ===== [GAS_MOD_xx] END =====`，缩进对齐所在代码块层级。
3. **编号**：`xx` 为全局递增编号；同一逻辑改动拆分到多处时可用 `xx` 加子编号（如 `07a`/`07b`）。
4. **修改前(引擎原版)**：独立一行 `// 修改前(引擎原版):`，其下用 `/* */` 块注释**逐字**复制引擎原版代码，不得简化、不得改缩进。
5. **修改后(本项目, 新建)**：`// 修改后(本项目, 新建):` 说明改动意图；下方紧跟实际生效的新代码。
6. **新增文件**：整个文件体用 `START`/`END` 包裹（如 `GAS_MOD_09` 的 `AbilityTimerManager.h/.cpp`），`START` 下注明"新增文件"。
7. **include 语句**：新增的 `#include` 也用 START/END 包裹并标注对应编号。

## GAS_MOD_01 — GameplayCue `N*N` 重复触发修复（OnActive / WhileActive）

**文件**：`Private/GameplayEffect.cpp`
**函数**：`AddActiveGameplayEffectGrantedTagsAndModifiers`（GE 首次应用、预测路径）
**问题本质**：外层 `for (Cue : Def->GameplayCues)` 已遍历每个 Cue，引擎原版却在循环体内调用 `InvokeGameplayCueEvent(Spec, ...)`；该函数内部会**再次遍历全部 Cue**，于是 N 个 Cue → N×N 次触发。

### 修改前（引擎原版）
```cpp
// 外层已 for 遍历到某个 Cue
if (bInvokePredictedEffects)
{
    Owner->InvokeGameplayCueEvent(Effect.Spec, EGameplayCueEvent::OnActive);
    Owner->InvokeGameplayCueEvent(Effect.Spec, EGameplayCueEvent::WhileActive);
}
```

### 修改后（本项目，`GAS_MOD_01` 包裹，当前代码 4744 ~ 4785）
```cpp
//=====================================================================
// ===== [GAS_MOD_01] START=====
// 修改前(引擎原版):
/*
Owner->InvokeGameplayCueEvent(Effect.Spec, EGameplayCueEvent::OnActive);
Owner->InvokeGameplayCueEvent(Effect.Spec, EGameplayCueEvent::WhileActive);
// 缺陷: InvokeGameplayCueEvent(Spec) 内部会再次遍历 Def->GameplayCues 全部 Cue,
//       而外层 for 已遍历每个 Cue => 外层 x 内层 = N*N 次触发。
*/
// 修改后(本项目, 新建): 仅对当前 Cue 内联构造参数并直接 HandleGameplayCues, 降为 O(N),
// 同时补全 RawMagnitude / NormalizedMagnitude / bGameplayEffectActive。
//=====================================================================
FGameplayCueParameters CueParameters(Effect.Spec);
if (Cue.MagnitudeAttribute.IsValid())
{
    if (const FGameplayEffectModifiedAttribute* ModifiedAttribute = Effect.Spec.GetModifiedAttribute(Cue.MagnitudeAttribute))
    {
        CueParameters.RawMagnitude = ModifiedAttribute->TotalMagnitude;
    }
    else
    {
        CueParameters.RawMagnitude = 0.0f;
    }
}
else
{
    CueParameters.RawMagnitude = 0.0f;
}
{
    const float Level = Effect.Spec.GetLevel();
    const float Range = Cue.MaxLevel - Cue.MinLevel;
    CueParameters.NormalizedMagnitude = (Range > KINDA_SMALL_NUMBER) ? ((Level - Cue.MinLevel) / Range) : 1.f;
}

FGameplayEffectQuery EffectQuery;
EffectQuery.EffectDefinition = Effect.Spec.Def->GetClass();
CueParameters.bGameplayEffectActive = Effect.Spec.Def->DurationPolicy == EGameplayEffectDurationType::Instant || GetActiveEffectCount(EffectQuery) > 0;

if (AActor* ActorAvatar = Owner->AbilityActorInfo.IsValid() ? Owner->AbilityActorInfo->AvatarActor.Get() : nullptr)
{
    UGameplayCueManager* CueManager = UAbilitySystemGlobals::Get().GetGameplayCueManager();
    CueManager->HandleGameplayCues(ActorAvatar, Cue.GameplayCueTags, EGameplayCueEvent::OnActive, CueParameters);
    CueManager->HandleGameplayCues(ActorAvatar, Cue.GameplayCueTags, EGameplayCueEvent::WhileActive, CueParameters);
}
// ===== [GAS_MOD_01] END =====
//=====================================================================
```

**要点**：单 Cue 触发从 O(N²) 降为 O(N)；同时补全了 `RawMagnitude`、`NormalizedMagnitude`、`bGameplayEffectActive` 的赋值，语义与引擎 `InvokeGameplayCueEvent(Spec)` 内部逻辑等价但只作用于当前 Cue。

## GAS_MOD_03 — StackOverflow 边界判定修复

**文件**：`Private/GameplayEffect.cpp`
**函数**：`FActiveGameplayEffectsContainer::HandleActiveGameplayEffectStackOverflow`
**问题本质**：引擎用 `==` 判"是否已达堆叠上限"，存在两个边界缺陷。

### 修改前（引擎原版）
```cpp
// allow refreshing duration and context ...
using namespace UE::GameplayEffect;
const bool bAtStackLimit = OldSpec.GetStackCount() == StackedGE->StackLimitCount;
```

### 修改后（本项目，`GAS_MOD_03` 包裹，当前代码 3709 ~ 3720）
```cpp
//=====================================================================
// ===== [GAS_MOD_03] START=====
// 修改前(引擎原版):
/*
const bool bAtStackLimit = OldSpec.GetStackCount() == StackedGE->StackLimitCount;
// 缺陷:
//   1) GE 未配置堆叠上限(StackLimitCount==0)且当前层数为 0 时, 会被误判为已到上限;
//   2) 用 == 而非 >=, 在层数被 FMath::Min() 截断/归并的路径下不够健壮。
*/
// 修改后(本项目, 新建): 先用 bHasStackLimit 兜底(未设上限则永不判到顶), 再以 >= 判定是否到达上限。
//=====================================================================
const bool bHasStackLimit = StackedGE->StackLimitCount > 0;
const bool bAtStackLimit = bHasStackLimit && OldSpec.GetStackCount() >= StackedGE->StackLimitCount;
// ===== [GAS_MOD_03] END =====
//=====================================================================
```

**修复点说明**：
1. **未设上限误判**：当 GE 未配置堆叠上限（`StackLimitCount == 0`）且当前层数为 `0`（如首次应用尚未叠加）时，引擎原版 `0 == 0` 会误判 `bAtStackLimit == true`，从而错误进入"刷新/Overflow 应用"分支。`bHasStackLimit` 兜底后，未设上限则永不判到顶。
2. **`==` 改 `>=`**：层数可能经 `FMath::Min()` 截断/归并后恰等于上限，用 `>=` 判定更健壮。
> 注：`bAtStackLimit` 之后仅影响 `bRefreshToLimit` 的计算与函数返回值；该函数内 `OverflowEffects` 的应用逻辑与引擎保持一致，未作改动。

## GAS_MOD_04 — PRAGMA 屏蔽 UE5.8 弃用告警（GetInstancingPolicy）

**文件**：`Private/AbilitySystemBlueprintLibrary.cpp`
**函数**：`UAbilitySystemBlueprintLibrary::HasAnyAbilitiesByPredicate`
**问题本质**：UE 5.8 将 `GetInstancingPolicy()` 标记为废弃（Deprecated），直接调用会产生弃用告警；项目仍需读取实例化策略做兼容判定。

### 修改前（引擎原版）
```cpp
if (!bOnlyRunPredicateOnAbilityCDOs && Spec.Ability->GetInstancingPolicy() != EGameplayAbilityInstancingPolicy::NonInstanced)
{
    AbilitiesToCheck.Append(Spec.GetAbilityInstances());
}
else
{
    AbilitiesToCheck.Add(Spec.Ability);
}
```

### 修改后（本项目，`GAS_MOD_04` 包裹，当前代码 1562 ~ 1581）
```cpp
//=====================================================================
// ===== [GAS_MOD_04] START=====
// 修改前(引擎原版):
/*
if (!bOnlyRunPredicateOnAbilityCDOs && Spec.Ability->GetInstancingPolicy() != EGameplayAbilityInstancingPolicy::NonInstanced)
{
    AbilitiesToCheck.Append(Spec.GetAbilityInstances());
}
else
{
    AbilitiesToCheck.Add(Spec.Ability);
}
// 问题: UE5.8 已将 GetInstancingPolicy() 标记为废弃(Deprecated), 直接调用会产生弃用告警。
*/
// 修改后(本项目, 新建): 用 PRAGMA_DISABLE_DEPRECATION_WARNINGS / PRAGMA_ENABLE_DEPRECATION_WARNINGS
// 包裹该调用, 屏蔽 UE5.8 的弃用告警, 保持向后兼容。
//=====================================================================
PRAGMA_DISABLE_DEPRECATION_WARNINGS
if (!bOnlyRunPredicateOnAbilityCDOs && Spec.Ability->GetInstancingPolicy() != EGameplayAbilityInstancingPolicy::NonInstanced)
{
    AbilitiesToCheck.Append(Spec.GetAbilityInstances());
}
else
{
    AbilitiesToCheck.Add(Spec.Ability);
}
PRAGMA_ENABLE_DEPRECATION_WARNINGS
// ===== [GAS_MOD_04] END =====
//=====================================================================
```

**要点**：改动不改变任何运行逻辑，仅通过 `PRAGMA_DISABLE/ENABLE_DEPRECATION_WARNINGS` 临时屏蔽 `GetInstancingPolicy()` 的 UE5.8 弃用告警；`if/else` 分支（取 Ability 实例 或 CDO）逻辑与引擎完全一致。

### `GAS_MOD_09`（续）— 刻度防溢出（`Delta` 钳制 + 整轴归一化）

> 同属 `AbilityTimerManager.h/.cpp`，共用标记 `GAS_MOD_09`。
> 背景：`FAbilityTimerAxis::Counter` 是 `int32` 且**没有运行时重置入口**（唯一归零机会是轴首次创建），长期运行或误传大 `Delta`
> 会让 `++Counter` 触发有符号溢出（UB）；一旦环绕，**溢出前已注册**的 Timer 会因 `ExpireTime(正) > Counter(负)` 而永久不再触发，
> 且不报错、不崩溃（表现为"一半效果正常、一半静默卡死"）。

**修改前（本项目早期写法）**：

```cpp
void TickTimeline(ASC, FGameplayTag InTiming, int32 Delta)
{
    if (!ASC || !InTiming.IsValid()) { return; }

    for (int32 Step = 0; Step < Delta; ++Step)
    {
        ...
        const int32 CurrentCounter = ++Axis->Counter;   // 无上下界保护，可溢出
```

**修改后（本项目）**：

```cpp
// 文件级防御常量（匿名 namespace）
constexpr int32 MaxDeltaPerCall = 256;               // 单次推进步进上限
constexpr int32 TimelineRebaseThreshold = 1 << 30;   // 归一化阈值

// ① 入口：无效 Delta 忽略；过大 Delta 警告后钳制
if (Delta <= 0) { return; }
if (Delta > MaxDeltaPerCall)
{
    UE_LOG(LogGameplayEffects, Warning, TEXT("[GAS_MOD_09] TickTimeline 收到过大的 Delta=%d，已钳制为 %d。..."), ...);
    Delta = MaxDeltaPerCall;
}

// ② 每轴推进前：逼近 int32 上限则整轴平移归一化
if (Axis->Counter >= TimelineRebaseThreshold)
{
    RebaseAxis(*Axis, TimelineRebaseThreshold);
}
const int32 CurrentCounter = ++Axis->Counter;

// ③ 新增私有方法（Public/AbilityTimerManager.h 声明，Private 实现）
void FAbilityTimerManager::RebaseAxis(FAbilityTimerAxis& InAxis, int32 InRebase)
{
    for (FTimerHandle Handle : InAxis.TimerHandles)
    {
        if (FTimerData* Data = FindTimer(Handle)) { Data->ExpireTime -= static_cast<double>(InRebase); }
    }
    InAxis.Counter -= InRebase;
}
```

**要点**：

- 归一化**语义等价**：判定只看差值 `ExpireTime - Counter`（`<=` 判定与 `GetAbilityTimerRemaining` 都是差值），整轴同步平移不影响触发时机、同轴触发顺序与返回值；
- 平移后 `ExpireTime` 不会为负——不变式保证轴上任一 Timer 都有 `ExpireTime >= Counter`（未到期者在未来，循环 Timer 顺延到 `Counter + Rate`）；
- 阈值取 `1<<30` 而非 `INT32_MAX`，是为 `++Counter` 与 `Counter + Rate` 留出加法余量；
- **注意行为变化**：`Delta > 256` 不再如实执行（仅打警告后钳制），"一次快进很多回合"需分批调用。

## GAS_MOD_14 — `FindStackableActiveGameplayEffect` 提为 `public`

**文件**：`Public/GameplayEffect.h`（`struct FActiveGameplayEffectsContainer`）
**函数**：`FActiveGameplayEffect* FindStackableActiveGameplayEffect(const FGameplayEffectSpec& Spec)`

**修改前（引擎原版）**：该函数位于 `private` 段（该段自 `private:` 起一直延续到类尾），`FActiveGameplayEffectsContainer` 外部无法调用。

```cpp
private:
    ...
    /** Helper function to find the active GE that the specified spec can stack with, if any */
    UE_API FActiveGameplayEffect* FindStackableActiveGameplayEffect(const FGameplayEffectSpec& Spec);
    ...
```

**修改后（本项目）**：在函数前后各切一次访问级别，单独把该函数提到 `public`，其余成员可见性不变。

```cpp
    // ===== [GAS_MOD_14] START=====
    // 修改前(引擎原版): 位于 private 段，外部无法调用。
    // 修改后(本项目): 提升为 public（仅访问级别变化，签名/实现/ABI 不变）。
public:
    /** Helper function to find the active GE that the specified spec can stack with, if any */
    UE_API FActiveGameplayEffect* FindStackableActiveGameplayEffect(const FGameplayEffectSpec& Spec);

private:
    // ===== [GAS_MOD_14] END =====
```

**说明与注意**：

- 仅调整访问级别：函数签名、实现、行为、序列化与 ABI 均不变（函数本身已带 `UE_API` 导出，跨模块链接无需额外处理）。
- **外部调用仍有一层前提**：`UAbilitySystemComponent::ActiveGameplayEffects` 是 `protected`，而公开访问器只有
  `UE_API const FActiveGameplayEffectsContainer& GetActiveGameplayEffects() const`（返回 **const**）。本函数是非 `const` 成员、
  返回非 `const` 指针，因此**若要从 `ASC` 外部调用，还需补一个非 `const` 的 `GetActiveGameplayEffects()` 重载**（当前**尚未添加**）。
  在 `FActiveGameplayEffectsContainer` 自己的成员函数内（如 `ApplyGameplayEffectSpec` 中）调用不受此限。

## GAS_MOD_16 — 新增文件 `TurnActionAbilitySystemComponent.h/.cpp`（回合制 ASC 子类）

**文件**：`Public/TurnActionAbilitySystemComponent.h` + `Private/TurnActionAbilitySystemComponent.cpp`（全新文件，整体为相对引擎的新增内容，**零引擎源码改动**）

**动机**：回合制下需要「知道 GE 何时挂上、何时卸下、现在推到第几轮」，而：

- 引擎既有的 GE 生命周期委托（`OnActiveGameplayEffectAddedDelegateToSelf` / `OnAnyGameplayEffectRemovedDelegate` / `OnGameplayEffectRemoved_InfoDelegate`）都是**原生** `DECLARE_MULTICAST_DELEGATE`、且不是 `UPROPERTY` → **蓝图绑不上**；
- 引擎没有「时间轴推进」这个事件；
- 各时机刻度由 `FAbilityTimerManager` 在权威端维护，**不随 ASC 复制** → 客户端拿不到轮次。

**做法**：把以上能力全部放进一个 ASC 子类 `UTurnActionAbilitySystemComponent`。

| 能力 | 实现手段 | 依赖的 API 是否公开 |
|------|---------|-------------------|
| 取组件（蓝图可用） | `static UTurnActionAbilitySystemComponent* GetTurnActionAbilitySystemComponent(AActor*)` —— 等价于 `GetAbilitySystemComponent(Actor)` + `Cast` | ✅ `UAbilitySystemGlobals::GetAbilitySystemComponentFromActor()` |
| 蓝图事件：`OnTimelineTicked` / `OnTurnBasedEffectAdded` / `OnTurnBasedEffectRemoved` | 子类自建 `DECLARE_DYNAMIC_MULTICAST_DELEGATE` + `UPROPERTY(BlueprintAssignable)` | — |
| GE 挂载事件来源 | `OnRegister` 里绑 `OnActiveGameplayEffectAddedDelegateToSelf` | ✅ public 成员 |
| GE 卸载事件来源 | `OnRegister` 里绑 `OnAnyGameplayEffectRemovedDelegate()` | ✅ public 访问器 |
| 「轴推进」事件来源 | `TickTimeline(Timing, Delta)` —— **唯一推进入口**：先调 `FAbilityTimerManager::TickTimeline`，再逐轴广播 | ✅ |
| 查询 | `GetTimelineRound` / `GetGameplayEffectTiming` / `GetGameplayEffectRemainingTicks` / `GetGameplayEffectElapsedTicks` | ✅ `GetActiveGameplayEffect()`、`GetTimelineCounter()`、`GetAbilityTimerRemaining()`、`AbilityTimingTags::ResolveOrDefault()`、`UGameplayEffect::Timing`、`FActiveGameplayEffect::DurationHandle` 全部 public |
| 客户端轮次（复制） | override `GetLifetimeReplicatedProps`，新增 `TArray<FTurnTimelineCounter> TimelineCounters`（`ReplicatedUsing = OnRep_TimelineCounters`）；客户端在 OnRep 中 diff 并广播 | ✅ |

**三点关键行为（易踩坑，已固化在代码注释里）**：

1. **挂载回调会重复触发**：新 `FActiveGameplayEffect` 初始 `bIsInhibited = true`，随后由 `SetActiveGameplayEffectInhibit` 激活；因此 `OnActiveGameplayEffectAddedDelegateToSelf` 在「抑制恢复」时会再次广播。子类按 `FActiveGameplayEffectHandle` 去重，重复的那次标记 `bIsReactivation = true`。
2. **卸载回调的时机**：`OnAnyGameplayEffectRemovedDelegate` 在 `InternalRemoveActiveGameplayEffect` 内、`07f` Timer 清理**之前**广播，故此刻仍可查剩余刻数；子类用 `Remaining > 0` 判定「提前移除」。
   - ⚠️ 不能走 `GetGameplayEffectRemainingTicks`：它内部用 `GetActiveGameplayEffect` 查表，而此刻 Effect 已被标记 `IsPendingRemove`，会被跳过。代码里直接问管理器。
3. **刻度「写读两侧」双轨**：权威端实时查管理器；客户端读复制副本。首份副本只登记镜像、**不广播**推进事件（否则玩家加入时会凭空产生一批 tick）。

**推进入口纪律（重要）**：本项目规定**唯一**推进入口是 `UTurnActionAbilitySystemComponent::TickTimeline(Timing, Delta)`。配套地，旧的蓝图入口 `UAbilitySystemBlueprintLibrary::TickTimeline` 已经过「先弃用、后删除」两步**整体移除**（`GAS_MOD_12` 小节），因为它不经过子类 → 不会同步刻度复制副本、不会广播 `OnTimelineTicked`，客户端轮次会停在旧值。

**落地注意**：

- 新增文件需要 **重新生成工程文件**（右键 `.uproject` → Generate Project Files / 重新编译）才会被 UBT 纳入。
- 需要把工程里所有 ASC 换成该子类（C++ 的 `CreateDefaultSubobject`、蓝图里添加的 ASC 组件要**替换组件类型**而非新建），否则收不到任何事件。
- 构造函数里已置 `bTurnBased = true`（「类型即语义」）并 `SetIsReplicatedByDefault(true)`。
- `FActiveGameplayEffect` 会被容器**原地复用**，故卸载时必须清理 `KnownEffectHandles` / `EffectStartCounters`（已处理）。

- 每处均以"上装饰线 → `GAS_MOD_xx START` → … → `GAS_MOD_xx END` → 下装饰线"成对包裹；`START` 下的注释即为"修改前（引擎原版）"对照，`END` 上方的实际代码即"修改后（本项目）"。
- 回合制与多时间轴（时机 Tag）改动的完整设计、使用方式与风险见 `回合制改造方案.md`。
- 若引擎升级回刷本文件，优先重点核对这些标记块是否被覆盖。

# 《33号远征队》遭遇战触发机制

> 分析目标：拆解玩家在关卡内如何从探索态被拉入战斗场景——明雷敌人的触发方式、先制/被伏击判定、转场方式，并给出 UE 实现方案对比。
>
> 核心结论：本作是**明雷制**（敌人在场景中可见游荡，非踩地雷随机遇敌），玩家可主动先制（First Strike）或从背后伏击，也可能被敌人先碰到而进入战斗。但"探索态如何切到战斗态"的具体转场方式，公开资料存在盲区，需实机验证。
>
> 更新时间：2026-08-14

## 二、先制机制（First Strike）拆解

### 1. 主动先制 First Strike

- **明雷制**：敌人在场景中可见游荡，不是踩地雷随机遭遇。
- 接近敌人后按 **R1** 主动发起战斗，**我方先手行动一回合**。
- **关键机制细节（Maxroll 确认）**：First Strike 下，队伍行动顺序**严格按照编队界面设置的 active 顺序**执行，**忽略速度属性和 Pictos 先后手效果**。
  - ⚠️ 攻略作者标注这**很可能是一个 bug**（正常逻辑应仍考虑速度）。

### 2. LFS vs AFS（两种先制系统）

公开资料揭示存在两个"看似相似实则不同"的先制系统：

| 系统 | 全称 | 含义 | 影响 |
|---|---|---|---|
| **LFS** | Lumina First Strike | 通过 Lumina 机制获得的先制 | 与 Lumina 相关构筑绑定 |
| **AFS** | Advantage First Strike | 站位优势（背后/未发现）获得的先制 | 从有利位置发起 |

两者的交互是"微妙但重要"的差异，涉及先手权如何叠加判定。

### 3. 伏击先制 Ambush + 弱点先制打击

- **Gustave 的 Weak Point Alpha Strike** 是主要先制手段：
  1. First Strike 伏击开启战斗
  2. 用 **Free Aim（自由瞄准）** 射击敌人发光的弱点部位
  3. 每次命中约 **2 倍伤害** + 高 Break 积累
  4. 衔接 Break 技能 AoE 引爆
- PC 鼠标 Free Aim 手感约好 20%；主机端建议开启 Patch 1.2 的**自动辅助吸附**。

### 4. 被敌人先碰到（被动遭遇）

- 若玩家未主动发起，敌人发现玩家后会主动接近并触发战斗。
- 此时**先手权归敌方或正常判定**（无我方先制加成）。
- 具体"被碰到"的判定范围、是否可逃跑规避，公开资料未明确。

## 三、关卡结构（遭遇战的舞台）

- **大地图 + 小箱庭**：大地图连接多个小型箱庭关卡。
- 箱庭内有**存档点（远征旗）**，是安全区。
- **怪物会刷新**：离开/重进箱庭后敌人重新出现，支持刷资源。

## 四、转场方式（公开资料盲区，重点待验证）

"从探索态如何切到战斗态"是本文档最大的信息缺口。三种可能方案：

| 方案 | 描述 | 判断依据 |
|---|---|---|
| **A. 原地无缝切镜头** | 探索场景就是战斗场景，触发后仅切换相机机位（越肩→对峙），不加载新关卡 | 从已知"进入战斗用探索越肩相机 Blend 到对峙机位"推断，最符合本作表现 |
| **B. 独立战斗场地** | 加载独立战斗关卡（类似传统 JRPG 的地图→战斗切换） | 传统 JRPG 惯例，但本作明雷+即时战斗表现更像方案 A |
| **C. 原地 + 战斗区域圈定** | 原地切镜头，但用隐形碰撞圈限定战斗移动范围 | 折中方案，兼得无缝与演出可控 |

**倾向判断**：结合"明雷可见 + 主动 R1 触发 + 越肩 Blend 对峙"这些已知事实，**方案 A（原地无缝切镜头）最可能**。但这需要逐帧看转场瞬间是否有加载/黑屏/场景变化来坐实。

## 五、UE 实现方案对比

> 背景同状态机文档：Sandfall 官方确认全部 Gameplay 系统用蓝图实现。

### 方案 1：Level 内 Actor 碰撞触发 + 相机 Blend（对应转场方案 A）

```
明雷敌人 Actor（可见游荡，带 Sphere Collision 触发区）
  → 玩家进入触发区 + 按 R1 → 触发 OnOverlap
  → 相机：PlayerCameraManager 从越肩 Blend 到对峙机位（相机状态栈切换）
  → 切入战斗状态机（GameMode 状态切换，禁用探索输入，启用战斗输入）
```

- **优点**：无缝、演出流畅、实现简单（纯蓝图即可）。
- **缺点**：探索与战斗逻辑在同一 Level，需谨慎管理输入映射与 AI 行为切换。

### 方案 2：独立战斗 Level（对应转场方案 B）

```
触发 → 加载战斗 Level（Level Streaming / OpenLevel）
  → 战斗场景内初始化敌人阵列与相机
  → 结束 → 卸载回探索 Level
```

- **优点**：战斗与探索完全隔离，逻辑清晰。
- **缺点**：有加载感，与"明雷即时反应"的手感冲突，演出割裂。

### 方案 3：混合（推荐深入验证）

- 探索态与战斗态同 Level（方案 A），但**战斗区域用隐形碰撞圈限定**（方案 C）。
- 战斗演出（如灵墨大技能）用 `LevelSequence` 临时相机，播完销毁。
- 相机状态用**相机状态栈 + Blend**管理，避免频繁创建/销毁相机。

### 关键落地难点

1. **触发判定**：明雷敌人的"发现玩家"用 `Sphere Collision` 或视线检测（`Line Trace` + 视野锥），区分"玩家先制 / 敌人先发现"。
2. **输入映射切换**：探索态（移动/交互）↔ 战斗态（战轮/防御）用 `Input Mapping Context` 切换，或同一 Enhanced Input 的优先级切换。
3. **相机无感转场**：越肩→对峙的 Blend 曲线要短（<1s）且带速度缓动，避免突兀。

# 《33号远征队》回合制战斗状态机

> 分析目标：拆解 Reactive Turn-Based（反应式回合制）的完整状态流转，建立状态机模型，并映射到 UE 实现。
>
> 核心结论：这套系统没有发明新范式，而是把传统回合制的"决策层"和动作游戏的"时机操作层"叠在一起——我方回合做决策，敌方回合做实时操作。理解这个双层结构，所有机制都能串起来。
>
> 更新时间：2026-08-14

## 二、四大子系统的机制拆解

### 1. 行动顺序（Turn Order）

- **行动顺序条在屏幕顶部**，基于 **Agility（敏捷）** 属性，可视化"接下来谁行动"。
- 高敏捷可对慢速敌人打出 **双重回合（double-turn）**，速度增益下更明显。
- **决策重心的转移**：传统回合制问"这回合我用谁"，本作问"接下来 N 步的轮转怎么算"，策略预判前置。

### 2. AP 行动点（替代法力值）

| 项目 | 规则 |
|---|---|
| 起始 AP | 每回合约 3~5 点（随等级/构筑成长） |
| 获取 | 进战斗重置、每回合自然回复、**格挡成功 +1 AP**、部分技能（如 Gustave Overcharge +2） |
| 消耗 | 技能消耗 AP；基础攻击便宜或免费 |
| 附加 | 每消耗 1 AP → 5% Gradient 充能（后期解锁 Gradient Attack） |
| 负面 | Exhaust 状态会阻止获得 AP |

**设计意图**：AP 连接了防御与进攻——格挡越多、可爆发资源越足。这解决了传统回合制"憋大招攒蓝"的节奏拖沓问题，鼓励进攻而非龟缩。

### 3. 防御三选项（无被动防御）

本作**没有被动防御**，敌方每次攻击都要主动反应。三选一是剪刀石头布式反制：

| 防御 | 时间窗口 | 图标 | 效果 | 适用 |
|---|---|---|---|---|
| **格挡 Parry** | ~100-150ms（金环） | 金色 | 免疫伤害 + **+1 AP**；完整格挡多段连击触发**自动反击** | 可预测的单段/多段攻击 |
| **闪避 Dodge** | ~400ms（蓝环） | 蓝色 | 完全抵消伤害 | 快速多段攻击，最宽容 |
| **跳跃 Jump** | ~200ms（红箭头） | 红色 | 仅躲避**地面 AoE** | 地面范围攻击，用错方式会被打中 |

- **格挡链（Parry Chains）**：完整格挡多段连击（如 10 连）触发自动反击（约 1.5 倍返还伤害）+ 累积 **Resolve**（额外护盾 + 每回合 +1 AP）。
- **风险收益**：格挡窗口比闪避窄 3 倍，但收益高得多——这是难度曲线的手感来源。

### 4. Break 眩晕（独立姿态系统，非 HP）

Break 不是单纯眩晕，而是**敌人独立的姿态/稳定性条**（HP 下方的黄色条）：

```
积攒 Break → 触发 Break → 爆发收割 → 重复
```

1. **积累**：每次攻击积累，**完美 QTE 约 +20%**，通常 4~6 次完美填满。
2. **引爆**：达到 100% 后，必须主动用 **Break 标记技能**（如 Gustave 的 Detonate）引爆。
3. **效果**：敌人眩晕**失去下一次行动** + 一回合内受到约 **+50% 伤害**（所有来源）。
4. **进阶**：部分 Pictos 可延长眩晕至两回合，实现"无回合"锁死 Boss。

## 四、UE 实现映射

> ⚠️ 关键背景：Sandfall 在 GDC 2026 官方确认——**全部 Gameplay 系统用蓝图（Blueprint）实现，不用 C++**。因此下表用蓝图术语为主，附 C++/GAS 概念对照（方便与你已有的 GAS 文档沉淀衔接）。

| 状态机元素 | 蓝图实现（Sandfall 实际做法） | C++/GAS 概念对照 |
|---|---|---|
| 战斗状态机本体 | `GameMode/GameState` + 枚举状态机，或 Actor 上的 `State Machine` 蓝图节点 | 专用 `UWorldSubsystem` 战斗管理器 + `GameplayTag` 状态标签 |
| 行动顺序 Timeline | 按 Agility 排序的数组 + 索引指针轮转 | 排序算法 + 回合队列，或 GAS Ability 队列 |
| AP 资源 | Actor 上的 Float 变量 + 增减函数 | `AttributeSet` 自定义属性 + `GameplayEffect` |
| 技能/攻击 | `Gameplay Ability` 蓝图（Sandfall 用蓝图自定义技能系统） | `UGameplayAbility` + `UAbilityTask` |
| 格挡/闪避/跳跃 | 输入事件 + 分支 + 计时器判定 | 瞬发 `UGameplayAbility`，判定窗口用 `FTimerHandle` 或 `AnimNotify` |
| QTE 环形计时器 | UMG Widget + `Timeline` 节点驱动环旋转 | `UAbilityTask` + UMG，命中窗口对比时间戳 |
| Break 眩晕 | 敌人 Actor 上的 Break 条变量 + Stun 布尔 | `GameplayEffect`（Stun）+ `GameplayTag`（`State.Stunned`） |
| 防御反击链 | 格挡成功事件 → 触发反击技能 | `GameplayEvent` + `GameplayAbility` 触发 |

**核心落地难点（值得你重点拆）：**

1. **格挡判定窗口**：用 `Timer` 还是 `AnimNotify`？——推荐后者，判定时机与攻击动画"命中帧"强绑定，避免动画速率变化导致判定漂移。
2. **QTE 环形计时器的命中判定**：环转到目标区间的瞬间记录输入时间戳，与区间中心比对，分完美/标准/失败三档。
3. **行动顺序与实时防御的并发**：敌方回合内玩家做实时防御，这不是传统"等待回合结束"，而是**回合内嵌实时子状态**——蓝图里用独立的防御状态机（枚举 + Tick 检测输入）承载。

## 五、设计意图总结（为什么这么设计）

| 机制 | 解决的痛点 |
|---|---|
| AP 替代法力值 | 憋大招攒蓝的拖沓节奏 → 用防御换进攻资源 |
| 行动顺序 = 敏捷 | "用谁"变成"算接下来几步"，策略前置 |
| 防御三选一（剪刀石头布） | 敌方回合不躺平，持续给操作压力 |
| 招架窗口比闪避严 | 高风险高回报，难度曲线手感来源 |
| Break 独立于 HP | 给"防御特化/姿态特化"技能一个独立价值维度，不只看面板伤害 |

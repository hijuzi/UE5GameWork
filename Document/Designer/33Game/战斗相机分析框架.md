# 《33号远征队》战斗相机分析框架

> 分析目标：回答"一场战斗到底有几个相机"——通过三层模型拆解机位状态、运镜次数与技术实例，建立可复用的逐帧分析模板。
>
> 状态：框架已建立，部分结论为行业推断，待实机逐帧验证。
> 更新时间：2026-08-14

---

## 一、核心结论预览

"相机"在游戏里分三个层次，答案分别是：

| 层次 | 答案 | 说明 |
|---|---|---|
| 机位状态（Camera State） | **4~5 个** | 视角的"形态"，战斗大部分时间在这些状态间切换 |
| 运镜/镜头动画（Shot） | **N 次（动态）** | 实际动镜头的次数，随技能/格挡次数变化 |
| 技术实例（UE 侧） | **常驻 1 个 + 演出临时若干** | 底层实现，与"几个相机"是不同维度 |

---

## 二、相机三层模型（核心框架）

### 层次一：机位状态（约 4~5 个）

这是"视角的形态"，一场战斗大部分时间只在这些状态间切换：

| # | 机位状态 | 出现时机 | 表现 |
|---|---|---|---|
| 0 | 转场镜头（第 0 个关键镜头） | 进入战斗瞬间 | 探索越肩视角 Blend 到对峙机位，不属于战斗机位但极关键 |
| 1 | 对峙主相机 | 我方回合默认 | 中景/全景，我方 3 人列队 vs 敌方 3 人列队，镜头在角色侧后方 |
| 2 | 行动者聚焦 | 选择技能/角色行动 | 从对峙机位向当前行动角色推近 |
| 3 | 敌人特写 | 敌方回合攻击宣言、瞄准弱点 | 敌人入镜特写，交代攻击意图 |
| 4 | 格挡/闪避 QTE 机位 | 敌方攻击动画期间 | 保持中景但微调角度，保证 QTE 环形计时器与攻击轨迹同框 |
| 5 | 演出/结算机位 | 灵墨大技能、战斗结束 | 多镜头剪辑或收尾定格 |

### 层次二：运镜/镜头动画（Shot）

这才是"一场战斗实际动了几次镜头"的答案，它是**动态的**：

- **每次技能释放**：起手特写 → 命中侧拍/环绕 → 收招回位
  - 普通技能 2~3 个镜头
  - 灵墨大技能 3~5 个（多机位剪辑）
- **每次完美格挡/弹反**：时间膨胀 + 回弹推拉（zoom punch）+ 屏幕震动
- **杂兵战**：全程可能只动 10~20 次镜头
- **Boss 战**：光技能演出就 40+ 次

### 层次三：技术实例（UE 侧）

业内标准做法（33 号远征队大概率也是）：

| 类型 | 实现 | 说明 |
|---|---|---|
| 常驻主相机 | `PlayerCameraManager` + 相机状态栈/Blend | 机位切换是同一相机的参数变换或状态 Blend，**不是新建相机** |
| 临时演出相机 | `LevelSequence` 多机位轨（CameraCut） | 技能演出播完即销毁 |
| QTE 反馈 | `CameraShake` + FOV/Zoom punch + 慢动作 | 叠加在主相机上，**不是新机位** |

## 四、分析方法论（如何做一次逐帧拆解）

1. **选素材**：B 站/YouTube 无解说 Boss 战流程，避开有解说或剪辑的版本。
2. **粗拆**：先按机位状态（层次一）给整场标注，确认状态数量和切换逻辑。
3. **细拆**：对每次技能/格挡，逐帧数镜头移动（层次二）。
4. **验证**：用层次三的观察点，判断底层实现方式。
5. **对照**：与本文档 4~5 个机位框架对比，修正或补充分类。

## 五、证据可信度分层

**✅ 已确认（Devcom 演讲，2025.8 科隆）：**
- 敌人从 4 个减到 3 个，"目的是优化镜头表现和视觉清晰度"
- 专门开发工具让设计师**直接调整动画和镜头效果**
- 格挡系统投入精力最多，精细调了"敌人攻击动作、**摄像机角度**和动画速度"
- 战斗灵感：失落的奥德赛、P5、FFX、只狼、鬼泣

**⚠️ 推断（实机表现 + 行业惯例）：**
- 具体机位数量、LevelSequence 承载演出、CameraShake 实现 QTE 反馈——无官方文档，为专业推断，需逐帧验证。
